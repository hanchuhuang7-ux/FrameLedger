# 渲染恢复验证

## 多层 OpenEXR 的恢复对照

2026 年 11 月 26 日，使用 Blender 5.3.0 和 OpenEXR 3.4.10 独立验证。可复现镜头的多层 EXR 含 Combined、Depth、Normal 三个分部，每帧共 8 个通道。

| 检查 | 结果 |
| --- | --- |
| 参考库解码 17 个完整样本 | 15 个扫描线样本通过检查，2 个可读的 tiled 和 deep 样本正确转为待复核 |
| 截断与尺寸测试 | 在 15 个扫描线样本上分别裁掉最后 1 字节和 17 字节，30 个截断样本全部检出。15 次错误显示尺寸检查全部检出 |
| 格式覆盖 | Blender 的 11 个压缩选项、16/32 位浮点、交错多层与 multipart，以及带负坐标和倒序扫描线的数据窗口 |
| 实际中断和恢复 | 写出第 9 张后停止进程，另存 22 张补图，合并结果 31/31。独立解码全部 248 组帧与通道，与一次性完整渲染逐项一致 |
| 待复核保护 | 混合报告中有 1 张截断、20 张缺失及 1 张 tiled。补渲染只写入 21 张，帧号 1021 保留给人工复核 |

```sh
node tools/exr-corpus.mjs "/path/to/blender" ./test-results
node tools/blender-smoke.mjs "/path/to/blender" ./test-results exr
```

## 可复现的中断测试

2026 年 11 月 26 日，Blender 5.3.0 使用 Cycles CPU 渲染一个转动的立方体。镜头范围为 1001 至 1061，步长为 2，共 31 帧。测试程序启动一个独立后台进程，在 Blender 写完第 1017 帧后终止这个进程。

| 检查 | 观测结果 |
| --- | --- |
| 中断后检查主目录 | 9 帧通过，缺第 1019 至 1061 帧，步长 2，共 22 帧 |
| 按报告补渲染 | 单独目录写入 22 帧，两个目录合并检查得到 31/31 |
| 使用同一报告重试 | 已有补图 22 张逐张通过 SHA-256 检查，新增渲染 0 张 |
| 检查原始文件 | 主目录 9 张原图和保存的场景文件的 SHA-256 均与中断时一致 |
| Windows 共享目录 | 22 张补图、22 份摘要和状态文件的访问规则逐一与同目录新建文件核对一致 |
| 对照一次完整渲染 | 由 Blender 独立解码的 31 组像素逐帧相同，参考序列有 31 种不同画面 |

构建后运行下面的命令，最后一个参数是存放测试结果的父目录。每次运行都会生成新的子目录，内含场景、主目录、补图、参考图和 `verification.json`。

```sh
node tools/blender-smoke.mjs "/path/to/blender" ./test-results
```
